# قارئ الهاتف والطباعة وتخطيط الكاشير — 0.5.3

أُعيد استخدام صفحة الماسح الموجودة في مشروع الكاشير السابق وبروتوكول `/api/v1/market/scanner/:token/scan` نفسه. طلب التطبيق السابق `{barcode:...}` ما زال مقبولاً؛ لا يلزم تغيير البروتوكول أو استبدال شهادات TLS الحالية. صفحة `market-scanner.html` أصبحت الصفحة الفعلية بدلاً من صفحة الإرشاد، وهي ضمن المثبّت وتعمل دون CDN أو ملفات واجهة خارجية.

## الاستخدام

1. الهاتف والحاسوب على نفس الشبكة. استخدم إعداد HTTPS وعنوان الخادم والشهادة السابقة، مع السماح للمنفذ في شبكة Windows الخاصة. التفعيل التجاري للجهاز الرئيسي مطلوب لاتصال LAN.
2. من الكاشير افتح ربط الهاتف، وامسح QR بالتطبيق السابق. ويمكن فتح رابط الماسح في متصفح هاتف يدعم BarcodeDetector والكاميرا عبر HTTPS موثوق؛ إن لم يدعمها فاستعمل التطبيق السابق أو الإدخال اليدوي. إذن الكاميرا يحتاج موافقة المستخدم على الهاتف.
3. تظهر حالة اتصال الهاتف في الكاشير. إعادة تحميل صفحة الكاشير تحفظ الرابط ومؤشر المسح ضمن جلسة المتصفح، والانقطاع المؤقت يعاد بعده الاستطلاع. تسجيل الخروج أو انتهاء الجلسة/صلاحية الرابط أو إعادة تشغيل الخادم قد يستلزم ربطاً جديداً؛ لا تُستعاد جلسة منتهية.
4. خيار «طباعة الوصل بعد الحفظ» في أسفل الفاتورة. ألغِه لحفظ الفاتورة وترحيل المخزون والحسابات دون طباعة أو فتح نافذة الطابعة. يُحفظ الاختيار لهذا المتصفح. يمكنك تفعيله مجدداً أو طلب طباعة آخر وصل يدوياً دون إنشاء فاتورة ثانية. F8 يحفظ حسب الخيار المحدد.
5. على الحاسوب والتابلت، قائمة الأصناف وتفاصيل الفاتورة لهما تمرير مستقل. الشريط العلوي ثابت، والإجمالي والحفظ ثابتان بأسفل الفاتورة. على الشاشة الضيقة تبقى اللوحتان قابلتين للتمرير وأزرار الفاتورة قابلة للوصول.

## اختبارات نُفذت محلياً

- 32 اختبار Node/SQLite ناجحاً؛ واجهات التطبيق الـ16 وسيناريوهاتها نجحت بعد التعديل.
- اختبار HTTPS بشهادة اختبار مخصصة، وفتح صفحة الهاتف وتبادل الحالة وإيصال المسح إلى فاتورة الكاشير. الكاميرا ونتيجة فك الباركود محاكاتان في الاختبار، وليستا كاميرا هاتف فعلية.
- طلب المسح السابق بلا معرف إضافي يعمل. الصفحة المحدثة تضيف معرفاً اختيارياً يمنع تكرار الإضافة عند فقد الاستجابة وإعادة المحاولة؛ لا يغير ذلك عقد التطبيق السابق.
- انقطاع استطلاع مؤقت ثم إعادة الاتصال، واستعادة الرابط بعد إعادة تحميل صفحة الكاشير، وإلغاء الربط وإيقاف مسارات الكاميرا.
- حفظ دون طباعة مع ثبوت الفاتورة والمخزون، ثم حفظ مع الطباعة، وإعادة طباعة يدوية لا تضيف فاتورة.
- تمرير الأصناف والفاتورة بعجلة الماوس دون تحريك الأخرى، وثبات الشريط العلوي والإجمالي والحفظ. سحب لمس حقيقي ضمن محرك Chromium، وفحص شاشة ضيقة.
- صور 240 مادة واللمس والباركود وPDF التجربة ما زالت تنجح.

المصدر يحوي أوامر `npm run test:scanner` و`npm run test:pos-layout`؛ يحتاج الأخير قاعدة التجربة الناتجة من `npm run demo:create` أولاً. تُنفذ هذه الفحوص في Windows CI قبل بناء المثبّت وفحص التثبيت.

## ما يحتاج أجهزة العميل

لم يُفحص هاتف الماركت أو الكاميرا أو شهادة الهاتف أو جدار الحماية أو شبكة العميل فعلياً. يلزم مسح باركودات حقيقية بالتطبيق السابق، والتأكد من وصولها إلى الكاشير الصحيح، وتجربة فصل Wi-Fi وعودته، وتجربة حفظ فاتورة والطباعة معطلة ثم تشغيلها على الطابعة الفعلية. لا تُعدّ المحاكاة أو نجاح CI بديلاً عن هذا القبول الميداني.
