# المحاسب برو — Desktop Offline 0.5.0 (فرع تطوير)

نسخة محلية بقاعدة SQLite واحدة؛ لا تحتاج الإنترنت في التشغيل اليومي. واجهة الدسكتوب والكاشير الحاليان محفوظان. مرجع الوظائف مستودع المحاسب برو للشركات؛ لم تُعدّل نسخته السحابية.

## التشغيل والتحديث

يتطلب Node.js 24 وWindows لبناء المثبّت:

```powershell
git pull origin development/functional-desktop
npm ci
npm test
npm run desktop
```

عند التشغيل الأول: `admin` / `admin123`. غيّر كلمة المرور من الإعدادات. تُخزن كلمات المرور بتجزئة scrypt، وتُطبق صلاحيات الأقسام في الخادم. إذا كانت لديك بيانات دخول سابقة فاستخدمها.

## الوظائف الحالية

- مبيعات شركات مستقلة: عدة مواد، الرمز/الباركود/الاسم، الأسعار والخصم، العميل، المندوب، الفرع والمخزن، نقدي/آجل/مختلط. المسودة قابلة للتعديل والإلغاء؛ إرسالها يحجز المواد، ثم موافقة المدير، ثم التحميل الكامل أو على دفعات. كل دفعة تخصم كمياتها فقط وترحّل حصتها من البيع والمدفوع والتكلفة مرة واحدة، مع حجز الباقي. طباعة A4.
- كاشير مستقل: قائمة/بحث/بطاقة/باركود، تعليق وإتمام، وصل حراري عبر طباعة النظام. شكل الكاشير محفوظ؛ لا توجد طباعة صامتة أو تكامل درج نقدي.
- مشتريات متعددة المواد، الموردون والعملاء وكشوف حساباتهم، ترحيل المخزون والمبلغ المدفوع والذمم ضمن معاملة.
- مخازن ووحدات، أرصدة وحركات وتحويلات، حجوزات مؤرخة، جرد فعلي، واستيراد دليل المواد من CSV بعناوين `id,name,barcode,price,cost,category`؛ يمكن حفظه من Excel. استيراد XLSX الأصلي غير مضاف.
- مرتجعات مبيعات ومشتريات جزئية، تكلفة بيع محفوظة، توزيع الخصم، وحدود تمنع إرجاع أكثر من الكمية الأصلية.
- دليل حسابات، يومية وأستاذ وميزان مراجعة، عكس القيد اليدوي، قيد إقفال الإيرادات والمصروفات إلى الأرباح المحتجزة، وقفل الفترات وإعادة فتحها بعكس قيد الإقفال، أصول ثابتة واندثار شهري، موازنة سنوية ومقارنة فعلية.
- قبض وصرف وتسديدات أطراف، صندوق وبنك ومطابقة كشف، شفتات وفروق إغلاق، تقارير مالية ومخزنية وتصدير CSV.
- فروع ومندوبون، مستخدمون وصلاحيات، سجل تدقيق، بيانات الشركة، نسخة SQLite وتنفيذ استعادة عند إعادة التشغيل مع حفظ النسخة السابقة.
- تسجيل خمسة أجهزة كحد أقصى بقاعدة الخادم المحلي؛ المدير يحرر جهازاً قديماً من الإعدادات. هذا حد تشغيلي وليس نظام تفعيل تجاري موقعاً.

## حدود الاعتماد

هذه ليست شهادة اكتمال التكافؤ مع كل وظائف المحاسب برو. العملة الأساسية للدفاتر الدينار العراقي الصحيح والكميات أعداد صحيحة؛ سعر تكلفة الوحدة المعروض مقرب، أما القيمة الدفترية وتكلفة الصرف فمحفوظتان بدقة مع توزيع باقي التقريب. تدعم أسعار فواتير الشركات والمشتريات الدولار مع حفظ السعر المعتمد والعملة الأصلية، وتظل القيود بالدينار. مبالغ الدفع المباشر للفواتير تدخل بالدينار؛ لقبض أو دفع الدولار الفعلي استخدم سند الدولار في الصندوق والبنوك، الذي يحفظ رصيد الدولار والقيمة الدفترية وفروق الصرف المحققة. بقيت وحدات التحويل المركبة والكميات الكسرية وXLSX الأصلي والتفعيل التجاري بمفاتيح موقعة خارج هذه النسخة. تكاليف فواتير المبيعات القديمة التي لا تحمل لقطة تكلفة لا تُخمن تلقائياً؛ يمنع مرتجعها حتى المراجعة المحاسبية.

الربط المحلي: شغّل `npm start` على الجهاز الرئيسي مع `ALMAHASIB_HOST` مضبوطاً على عنوانه المحلي، ثم افتح `http://<server-ip>:3765` من الأجهزة الأخرى. قاعدة SQLite تبقى على الخادم؛ لا تفتح ملفها مباشرة من مشاركة الشبكة. يلزم اختبار جدار Windows والشبكة الفعلية. ربط Android يعيد استخدام تطبيق الماسح الموجود وبروتوكوله نفسه؛ لا يحتاج إعادة بناء. من الإعدادات اختر شهادة HTTPS بصيغة PEM ومفتاحها، وحدد الاسم/IP الذي تغطيه ومنفذ 3776، ثم أعد تشغيل البرنامج وأنشئ QR من الكاشير. يجب أن يكون عنوان الخادم قابلاً للوصول من الهاتف وأن يثق الهاتف بالشهادة. الشهادة الذاتية وحدها لا تثبت توافق ثقة تطبيق Android؛ لم نعطل تحقق TLS. يلزم اختبار الهاتف الفعلي وجدار الحماية. ملفات TLS تحفظ بجوار البيانات خارج ملف SQLite؛ احتفظ بنسختك الأصلية من الشهادة والمفتاح بشكل آمن.

## الاختبارات

`npm test` يفحص معاملات الشراء والبيع والحجز والتحميل والمرتجع والجرد، توازن القيود، تكلفة الشراء، استعادة فعلية، الصلاحيات، إقفال الفترة، عكس القيد، الاندثار، الموازنة، المطابقة البنكية، حدود الأجهزة وترحيل قاعدة قديمة.

لاختبارات واجهة Chromium الاختيارية:

```powershell
npm install --no-save --package-lock=false playwright@1.56.0
npx playwright install chromium
npm run test:ui
```

يفحص `npm run test:electron` تشغيل Electron والخادم وSQLite وتسجيل الدخول، ويستخدم مجلداً مؤقتاً لا قاعدة بياناتك. سير GitHub Actions يشغّل اختبارات Windows والمتصفح ثم يبني EXE ويرفقه كأثر اختبار. نجاح إعداد السير لا يعني نجاح تشغيله؛ تحقق من نتيجته قبل تسليم نسخة.

راجع [عقد التكافؤ وحالة التحقق](docs/ENTERPRISE_PARITY.md).

أضيفت اختبارات التحميل الجزئي وإرجاع المحمل ومنع التحميل المكرر، وحصة المدفوع وفروق التقريب، وقيد الإقفال وعكسه، ولقطة سعر الصرف وفروق الدولار، وبروتوكول الماسح عبر TLS مع عزل الجلسات. شهادات `tests/fixtures/test-only-*` للاختبار فقط ولا تدخل في المثبّت ولا تصلح للإنتاج.
